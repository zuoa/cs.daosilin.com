# CS Data Hub UI/UX 方案

> 版本：1.0  
> 更新：2026-08-27  
> 适用范围：公开赛季首页、选手榜单、选手详情、管理后台

## 1. 产品定位

这是一个面向 CS 社区赛事的统计与运营工具，服务两类核心用户：

- 观众与选手：快速找到赛季、比赛日、选手排名、称号和地图表现。
- 赛事管理员：配置杯赛、管理种子名单、执行采集、审核比赛是否进入统计。

页面的单一核心任务分别是：

- 首页：找到目标赛季。
- 赛季页：比较选手表现，并进入单个选手档案。
- 选手页：理解该选手的优势、趋势与完整数据。
- Admin：可靠地完成“配置 → 名单 → 采集 → 审核”工作流。

## 2. 设计方向

视觉概念为「战术数据终端」。它借用 CS 中的准星、雷达、比分板和赛后报告语言，但不模拟游戏 HUD，也不牺牲后台的可读性。

### 设计原则

1. 数据先于装饰：视觉强度优先用在排名、状态、异常和关键操作上。
2. 当前上下文始终清楚：管理操作必须明确作用于哪个杯赛、哪些比赛或哪些玩家。
3. 操作可恢复：剔除比赛与移出玩家库不是删除，界面应明确可以恢复。
4. 渐进式呈现：榜单先展示比较所需字段，详细数据通过行展开或选手详情承载。
5. 反馈紧随动作：异步操作包含加载、禁用、成功和失败状态，不静默失败。

### 识别性元素

准星/雷达是唯一的品牌化视觉元素，使用在品牌标识、首页数据概览和采集状态中。其他位置保持克制，避免图标与装饰噪声。

## 3. 信息架构

```text

│   ├── 选手搜索与排序
│   └── 快速展开 / 完整详情

    ├── 能力雷达与 Rating 趋势
    ├── 称号与荣誉
    ├── 地图表现
    └── 详细统计

管理后台

│   ├── 杯赛目录与配置
```

## 4. 视觉系统

### 色彩

| Token | 色值 | 用途 |
|---|---:|---|
| Ink 950 | `#0B111B` | Admin 侧栏、首页雷达底色 |
| Ink 900 | `#111A26` | 主要文字、比分与高对比区域 |
| Canvas | `#F2F5F6` | 页面背景 |
| Surface | `#FFFFFF` | 卡片、表格和表单 |
| Line | `#DFE6E9` | 边框与分隔线 |
| Signal | `#15966B` | 主操作、进行中、优秀数据 |
| Signal Dark | `#0E7653` | 高亮文字与 hover |
| Blue | `#3976A8` | 采集运行状态 |
| Amber | `#B77A24` | 提醒与辅助指标 |
| Danger | `#BF4747` | 失败、剔除等风险操作 |

Signal Green 是全站唯一主强调色。不能因为“看起来更丰富”而为普通卡片随机分配颜色。

### 字体

- 正文：`Inter / SF Pro Text / PingFang SC / system-ui`
- 标题和大数字：`DIN Alternate / Arial Narrow / SF Pro Display`
- ID、日期、排名与数据：`SFMono-Regular / Consolas / Menlo`

数字统一使用等宽数字特性，保证表格纵向比较稳定。

### 圆角与阴影

- 控件：7–9px
- 普通面板：11–16px
- 大型品牌容器：18–26px
- 卡片默认只使用细边框和极轻阴影；浮层、Toast 才使用强阴影。

### 间距

基础单位为 4px。常用间距：8 / 12 / 16 / 20 / 24 / 32 / 48 / 64px。

## 6. 组件规范

### 按钮

- Primary：每个视图默认最多一个视觉主操作。
- Subtle：返回、刷新、公开页跳转等安全操作。
- Danger：只用于会改变统计结果的剔除类操作。
- 图标按钮必须有 `aria-label` 与 `title`。
- 所有主要点击目标最小高度 42px，移动端 44px。

### 表格

- 表头使用紧凑等宽字和大写英文辅助标签。
- 数字使用等宽字体，文字左对齐，操作列右对齐。
- hover 只改变背景，不使用缩放，避免布局抖动。
- 宽表格在移动端横向滚动，不压缩到不可读。
- 多选后在表格上方展示批量操作条，清楚显示选中数量。

### 表单

- 标签始终可见，不依赖 placeholder 充当字段名。
- 新建、编辑单个实体使用模态弹框承载，主页面不长期平铺编辑表单。
- 弹框打开后锁定页面滚动、聚焦首个字段、限制 Tab 焦点范围，并支持 Esc 关闭。
- 名单维护、采集和比赛审核属于持续工作流，保留在当前杯赛上下文中，不放进弹框。
- 赛季统计范围使用日期时间选择器，开始与结束均精确到秒，按 Asia/Shanghai 业务时区解释；结束时间属于闭区间。
- 保存时禁用按钮并显示进行中状态。
- 错误通过靠近任务区域的 Alert 或全局 Toast 展示，并使用 `role="alert"`。
- 唯一标识在编辑模式下锁定，避免产生隐性主键变更。

### 状态

- 进行中/库内：绿色圆点 + 文字。
- 采集运行：蓝色圆点 + 轻微脉冲 + 文字。
- 已归档/非库内：中性灰 + 文字。
- 错误/剔除：红色 + 图标或文字，颜色不能成为唯一提示。

### 空状态与加载态

- 空状态说明为什么为空，并给出下一步。
- 数据加载使用固定高度容器和 spinner，避免页面跳动。
- 骨架屏只用于结构可预测的首页赛季卡片。

## 7. 关键交互

### 杯赛工作流

1. 创建或选择杯赛。
2. 顶部显示“当前杯赛”，后续操作全部作用于此上下文。
3. 从玩家库勾选种子，必要时手动输入额外 Player ID。
4. 执行采集，按钮进入禁用与运行状态，并每 4 秒轮询。
5. 在比赛记录中按比赛日筛选，批量纳入、剔除或恢复。

### 玩家库工作流

- 搜索与状态筛选采用 260ms 防抖，减少重复请求。
- 编辑玩家时唯一 ID 锁定；保存后清空表单并刷新列表。
- 单行状态切换和批量状态切换使用相同动词：加入 / 移出。

### 榜单工作流

- 默认按 Rating 排序，可切换 K/D、胜率、ADPR 和 MVP。
- 选手行的展开按钮只显示快速信息；箭头按钮进入完整详情。
- 行本身不绑定点击，避免键盘用户无法操作和误触。

## 8. 响应式规则

| 断点 | 行为 |
|---|---|
| ≥ 1240px | Admin 双栏编辑，首页三列赛季卡片 |
| 980–1239px | Admin 单栏，首页两列，选手图表上下排列 |
| 720–979px | Admin 侧栏转顶部导航，表单与工具栏换行 |
| < 720px | 卡片单列、KPI 两列、宽表横向滚动、44px 点击目标 |

必须验证宽度：375 / 768 / 1024 / 1440px。任何页面都不应出现页面级横向滚动；只有标记为 `.table-scroll` 或 `.day-scroll` 的局部容器允许滚动。

## 9. 可访问性

- 正文对比度不低于 WCAG AA 4.5:1。
- 所有交互控件有可见 `:focus-visible` 状态。
- 页面包含跳到主要内容的 skip link（Admin）。
- 表单 label 使用 `for` 关联 input。
- 图标不单独传达状态；配合文字或 `aria-label`。
- 动画遵循 `prefers-reduced-motion`。
- 有意义的头像提供 alt；纯装饰 SVG 使用 `aria-hidden`。

## 10. 文案规则

- 用用户认识的动作：保存杯赛、立即采集、剔除比赛、恢复比赛。
- 同一动作在按钮和反馈中使用同一名称。
- 不使用“提交”“操作成功”等模糊表达。
- 错误必须给出恢复方向，例如“请先选择比赛”“调整搜索条件”。
